レポート 3: TypeScript 実装パターンの不統一

対象: packages/react/src/**/*.parts.tsx と *.tsx（基準の button を除く）  /  基準: .opencode/skills/new-component/SKILL.md の実装パターン（A〜E）

実装パターンの問題は 4 系統に分かれます。

  • レンダリング API の 3 系統: 正規の系統は内部ラッパー _use-render.js の useRender（button-group が使用）です。しかし alert、avatar-group、resizable は Base UI の @base-ui/react/use-render を、button（基準）、chip、accordion、collapsible は splitRenderProps + useRenderElement を直接使っており、正規の系統に統一されていません。
  • 複合コンポーネント形式: ハンドルを公開するコンポーネント（field、fieldset、alert-dialog、dialog、drawer、menu、tooltip）は Object.assign と独自 interface で構成されており、基準の「export const X: Component<XProps> = function SuiX」と形が違います。
  • 構造の混乱: form、radio、switch のパーツファイルはセクション見出しと区切り線がなく、radio、switch、select、progress は型の並び順が基準と違います。
  • 型の緩さ: autocomplete と form に any が残っています。

レンダリング API の正規パターンは、button-group が使う内部ラッパー _use-render.js の useRender です。このラッパーは splitRenderProps と useRenderElement を内部に包み、useRender({ defaultTagName, ref, props, state, enabled, stateAttributesMapping }) の 1 点でデータ属性のマッピングなどを処理します。props の型は RenderProps<TState> を使います。基準とされてきた button の splitRenderProps + useRenderElement 直接使用は旧パターンです。

ハンドル系コンポーネント（dialog、menu、tooltip、alert-dialog、drawer）の Object.assign は、Base UI のハンドル（createHandle）をコンポーネントに紐付ける必要から生まれた形式です。一覧では「基準と形が違う」ことを指摘しつつ、その意図を注記しました。書き換える場合はジェネリクス（Value、Data など）の維持に注意してください。
