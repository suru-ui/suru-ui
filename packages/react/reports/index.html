検査の目的と方法

各コンポーネントの TypeScript 実装、CSS スタイリング、Storybook ストーリーについて、プロパティー、実装パターン、コメント、スタイリングパターンの一貫性を検査しました。

検査は 3 つの文書を基準に行いました。

  • .opencode/skills/css/SKILL.md（CSS の構造、変数グループ、レイヤー、整形の規約）
  • .opencode/skills/new-component/SKILL.md（パーツ構成、context、slotProps、JSDoc の規約）
  • .opencode/skills/jsdoc/SKILL.md（複数行 JSDoc、@default、@example の形式）

検出項目は違反の重大度で分類し、次の 4 つのレポートにまとめました。

レポート一覧

レポート 1: CSS スタイリングの不統一（98 件） セクション構成、変数目録と既定値設定の整合、変数参照、語彙コメント、セレクター、上書き設定などの規約違反をカテゴリーごとにまとめています。 レポート 2: JSDoc とコメントの不統一（88 件） namespace と別名の JSDoc 文言の揺れ、1 行形式 JSDoc、{@link} の誤参照、JSDoc 欠落、文言のゆらぎなどをコンポーネントごとにまとめています。 レポート 3: TypeScript 実装パターンの不統一（51 件） レンダリング API（useRender と useRenderElement）、複合コンポーネント形式、Sui プレフィックス、slotProps の優先順位、context の 4 点セット、any の使用などをまとめています。 レポート 4: Storybook ストーリーの不統一（34 件） 「使い方」の配置、バリエーション story の充足、controls の形式、候補ラベルの表示、args の既定値表記などをまとめています。

ソースのファイル数は CSS が 35（基準の button を除く）、ストーリーが 37（基準を含む）です。違反がなかったのは CSS が 8 ファイル、JSDoc が 3 ファイル、実装が 11 ファイル、ストーリーが 15 ファイルです。

全体的な傾向

  • JSDoc 文言の揺れが最も広範囲に及んでいます。overlays の 8 コンポーネントと autocomplete、combobox、select は「短縮名です」「短い名前です」を使い、基準の button は「別名です」です。
  • 1 行形式 JSDocは autocomplete と combobox の 2 ファイルに集中しています（合わせて 94 箇所）。他ファイルは複数行形式に統一されています。
  • 「静的」と「動的」の混在は forms と overlays に集中しています。基準の button は「静的」に var() 参照を置かない構成ですが、combobox、select は「静的」で var() を参照し、「動的」が欠落しています。
  • レンダリング APIは 2 系統に分かれています。基準は splitRenderProps + useRenderElement ですが、button-group、alert、avatar-group、resizable は Base UI の useRender を使っています。
  • 複合コンポーネント形式はハンドルを公開する component（dialog、menu、tooltip、alert-dialog、drawer）に限られており、Object.assign と独自 interface で構成されています。

補足

本レポートはコードの動作を変更するものではなく、スタイルの一貫性に絞った検査です。修正の要否と優先順位はチームで判断してください。

検査はスキル文書と基準実装の差分を主な根拠としています。Base UI 由来の環境変数（--transform-origin、--anchor-width など）のように、規約上は接頭辞なし変数の参照が禁止されるものの、フレームワークの都合で避けられない例については各レポートに注記しました。
