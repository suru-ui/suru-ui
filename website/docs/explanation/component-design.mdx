このページでは、Suru UI のコンポーネントがどのような部品の組み合わせでできているか、なぜそのような構造になっているかを説明します。Button は、設計を理解するための小さな具体例として使います。

## プリセットとパーツ [#preset-and-parts]

Suru UI のコンポーネントは、すぐに使えるプリセットと、それを構成するパーツに分かれています。プリセットは、一般的な構造とスタイルをあらかじめ組み立てたものです。パーツは、そのプリセットを構成する個々の要素です。

Button を例にすると、`Root` が外観と状態を持ち、`Content` がラベルを表示し、`Addon` が前後の補助要素を担当します。保留状態には `Pending` と `CircularProgress` が使われます。

この二層構造には、次の利点があります。

- よくある使い方は、プリセットをそのまま使えば完結します。
- 内部の一部だけを変えたい場合は、`slotProps` で調整できます。
- 構造そのものを変えたい場合は、パーツを直接組み立てられます。

すべてを最初からパーツで組み立てるのではなく、まずプリセットを使い、必要になった部分だけを下の層へ降りていく設計です。

## Base UI [#base-ui]

Suru UI の多くのプリセットは、Base UI のコンポーネントやユーティリティーを土台にしています。Base UI は、スタイルを持たない React 向けのコンポーネントライブラリーで、状態管理、キーボード操作、ARIA、描画要素の置き換えなどの低レベルな振る舞いを提供します。Suru UI はその上に、テーマ、外観、プリセットの構造を追加しています。

この分担により、Suru UI は見た目と使い方の一貫性に集中し、複雑なインタラクションの振る舞いは Base UI の実装を利用できます。`render`、`nativeButton`、`focusableWhenDisabled`、状態を引数に取る `className` や `style` などは、この土台から来ている代表的な props です。

## スロット [#slots]

スロットは、プリセットが内部で描画するパーツのうち、外部から props を差し込める名前付きの場所です。React の `children` や portal とは異なり、プリセットの内部構造に対する拡張点として設計されています。

`slotProps` は、スロット名をキーにしたオブジェクトです。プリセットの構造を保ったまま、内部の一部だけを調整できます。すべてのプリセットに `slotProps` があるわけではなく、スロットの名前や数もコンポーネントによって異なります。

スロットを用意する側には、内部構造をすべて公開せずに済むという利点があります。利用する側には、プリセットの更新に追従しやすいという利点があります。構造そのものを変えたい場合だけ、パーツの直接組み立てを検討します。

## 状態と外観 [#state-and-appearance]

Suru UI では、外観を選ぶ props と、操作に応じて変化する状態を分けて考えます。

Button の `variant`、`color`、`size` は外観を決める props です。一方、ホバー、アクティブ、フォーカス、無効、保留は状態です。外観の props と状態を分けることで、同じ見た目の部品を、さまざまな状態で一貫して使えます。

状態に応じたスタイルは、`className` や `style` に関数を渡すことで表現できます。コンポーネント固有のクラス名や CSS 変数を使う方法もありますが、まずは公開されている props と状態の仕組みを使うのが基本です。

## パーツ構成 [#part-composition]

プリセットの構造や順序が要件に合わない場合は、パーツを直接組み立てます。パーツをまとめたモジュールを `import * as` で名前空間として読み込むと、どのパーツがどのコンポーネントに属するかが明確になります。

```tsx
import * as ButtonParts from "./button";

export function CustomButton() {
  return (
    <ButtonParts.Root color="blue">
      <ButtonParts.Content>保存</ButtonParts.Content>
    </ButtonParts.Root>
  );
}
```

この例の `./button` は、パーツをまとめたモジュールの例です。実際のインポート元は、利用するパッケージが公開しているエントリーポイントに置き換えてください。パーツの公開状況はパッケージのバージョンによって異なります。

パーツを直接扱う方法は柔軟ですが、プリセットの内部構造に依存します。プリセットや `slotProps` で目的を達成できる場合は、そちらを優先すると、変更に強いコードになります。

## スタイルとアクセシビリティ [#styling]

コンポーネントのスタイルは、テーマのトークン、CSS 変数、CSS カスケードレイヤーを使って構成されています。

- 色、余白、文字サイズなどの値は、テーマのトークンから供給されます。
- 基本的なスタイルは `sui.component` レイヤーに、無効や保留などの状態は `sui.important` レイヤーに定義されます。
- リセットは、`sui_` を含むクラス名を持つ要素にのみ適用されます。

この構造により、アプリケーション全体のスタイルとコンポーネントのスタイルが衝突しにくくなっています。アプリケーション側の通常の CSS はレイヤーの外側にあるため、クラスや CSS 変数による上書きが優先されます。

見た目を大きく変える場合は、まず `variant` や `color` などの props を検討し、足りない部分だけを `slotProps`、CSS 変数、追加のクラスで調整するのがよいでしょう。

**アクセシビリティ**

コンポーネントの見た目を再利用する場合でも、要素の意味は用途に合わせて保つ必要があります。

- フォームの送信や画面内の操作には button を使います。
- ページ遷移にはリンクを使います。
- アイコンだけの操作には `aria-label` で名前を付けます。
- 無効と処理中を区別し、処理中はフォーカスや読み上げにも配慮します。

Button が既定でネイティブの button 要素を描画するのは、キーボード操作やフォーカス、スクリーンリーダーへの読み上げを、ブラウザーと要素の標準的な挙動に任せるためです。見た目を別の要素に移す場合も、この意味を失わないようにしてください。

**まとめ**

Suru UI のコンポーネント設計は、次の考え方にまとめられます。

- まずプリセットを使い、必要に応じて `slotProps` で内部を調整します。
- 構造を変える場合は、パーツを名前空間として組み立てます。
- Base UI の振る舞いと、Suru UI の外観・テーマを分けて考えます。
- 外観は props とトークンを優先し、CSS は補助的に使います。
- 要素の意味とアクセシビリティを保ちます。
